On medium and large Cacti installations, poller.php can keep running long after Spine has finished, because Boost processes poller output one small write at a time. This page explains why and sets out a plan, tracked upstream in Cacti issue 6569.

Status: proposal. None of this is implemented. It needs review by the Cacti maintainers before any code is written, because it touches the database layer and the poller core.

Background

Boost batches poller results so Cacti can update RRD files on a schedule instead of every polling cycle. Results land in poller_output_boost, and a later batch drain writes them to RRD files.

Root causes

The same results are written up to three times

Both data collectors, cmd.php and Spine, insert each result into poller_output, and with Boost's redirect option on they also insert it into poller_output_boost. Boost's on-demand path then copies the processed output a third time.

Metadata is looked up per data source

The batch drain runs separate queries for each data source's unused names, RRD file name and template, which adds up to tens of thousands of small queries per batch on a large install.

Inserts are built by string concatenation

Every insert is assembled in PHP and sent as SQL. There is no bulk-load path such as LOAD DATA LOCAL INFILE and no prepared batching.

Plan

In priority order, as three or four separate pull requests:

  1. Add a bulk-load helper to the database layer that uses LOAD DATA LOCAL INFILE from a temporary CSV file, falling back to multi-row INSERT where local infile is disabled.
  2. Use it in Boost's on-demand path instead of string-built inserts.
  3. Skip the redundant copy when output is already redirected to Boost.
  4. Load unused data source names and RRD templates once before the batch loop instead of per data source.
  5. Clean up poller_output after Boost has processed it.
  6. Rate-limit output processing in the main poller loop.

How it will be measured

Each change will be timed on the same machine before and after, against the time from the end of a Spine cycle to the end of poller.php. No speed-up is claimed until those numbers exist.
